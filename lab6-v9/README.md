# Лабораторная работа №6 (вариант 9). Фильтр аудита действий пользователя

Отдельный Maven-проект (`war`), группа `kz.edu`, artifactId `web-service-lab6-v9`.

## Что реализовано

- **`AuditFilter`** (`/*`) — индивидуальное задание, **вариант 9**. Для каждого запроса записывает в журнал: время, логин (из `HttpSession`, иначе «аноним»), IP, метод, URL, параметры и HTTP-статус. Значение параметра `password` заменяется на `***`. Запись делается после `chain.doFilter()`, поэтому виден итоговый статус; логин запоминается до вызова цепочки, чтобы действие «выход» тоже попало в журнал.
- **`AuditLog`** — хранилище последних 50 записей в памяти.
- **`AuthFilter`** (`/admin/*`) — пускает только вошедших, остальных перенаправляет на `login.html`.
- **`login.html` + `LoginServlet` (`/login`) + `LogoutServlet` (`/logout`)** — вход/выход через Session. Пароль не проверяется — учебная демонстрация.
- **`AuditServlet` (`/admin/audit`)** — защищённая страница с журналом: карточки-сводка и таблица действий.
- **`ActionServlet` (`/admin/action?type=create|edit|delete`)** — имитация действий; неизвестный тип даёт 400 (виден в журнале как ошибка).

## Запуск

JDK 17+, Maven 3.9+.

```bash
mvn clean package
mvn jetty:run
```

- http://localhost:8080/web-service-lab6-v9/login.html — вход
- http://localhost:8080/web-service-lab6-v9/admin/audit — журнал (без входа перенаправит на логин)
- http://localhost:8080/web-service-lab6-v9/logout — выход

## Проверка

1. Открыть `/admin/audit` без входа → редирект на `login.html`.
2. Войти с любым логином → открывается журнал; запрос входа записан, пароль скрыт (`password=***`).
3. Нажать «Действие: …» → в журнале появляются записи с логином пользователя.
4. «Неверное действие» → запись со статусом 400.
5. В консоли сервера видны строки `[Audit]`.
