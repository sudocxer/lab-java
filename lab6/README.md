# Лабораторная работа №6. Фильтры и обработка HTTP-запросов

Maven-проект (`war`), группа `kz.edu`, artifactId `web-service-lab6`.

## Что реализовано

- **`LoggingFilter`** (`/*`) — журналирует все запросы в консоль (практическое задание).
- **`AuthFilter`** (`/admin/*`) — проверяет `username` в `HttpSession`; неавторизованных перенаправляет на `login.html`, запомнив запрошенный URL (после входа пользователь попадает туда, куда шёл).
- **`TimingFilter`** (`/*`) — индивидуальное задание, **вариант 4**: измеряет время выполнения Servlet (`System.nanoTime()` до и после `chain.doFilter()`), пишет в консоль `[Timing] GET /… -> 200, 12.34 ms` и сохраняет результат в `RequestStats`.
- **`login.html` + `LoginServlet` (`/login`) + `LogoutServlet` (`/logout`)** — вход/выход через Session. Пароль не проверяется — учебная демонстрация.
- **`DashboardServlet` (`/admin/dashboard`)** — защищённая панель после входа: карточки (число запросов, среднее и максимальное время), таблица последних запросов с цветными полосками длительности.
- **`SlowServlet` (`/admin/slow?ms=N`)** — защищённый Servlet с задержкой для наглядной проверки `TimingFilter`.

Порядок фильтров при совпадении URL в аннотациях контейнером не гарантируется; здесь он и не важен, так как фильтры независимы.

## Запуск

JDK 17+, Maven 3.9+.

```bash
mvn clean package
mvn jetty:run
```

- http://localhost:8080/web-service-lab6/login.html — вход
- http://localhost:8080/web-service-lab6/admin/dashboard — панель (без входа перенаправит на логин)
- http://localhost:8080/web-service-lab6/admin/slow?ms=800 — запрос с задержкой 800 мс
- http://localhost:8080/web-service-lab6/logout — выход

## Проверка

1. Открыть `/admin/dashboard` без входа → редирект на `login.html` с сообщением «Доступ закрыт».
2. Войти с любым логином → открывается панель.
3. Нажать «Запрос 300 мс» / «Запрос 1200 мс» → в таблице появляются запросы с соответствующим временем.
4. В консоли сервера видны строки `[Request]` и `[Timing]`.
